## Implementation

- `Hub.holder_activity(session)` returns a fingerprint of the writes a live
  holder makes: locker `updated` and `cursor`, the highest message id it sent,
  and the `(resource, expires)` of the ticket claims it holds. The session
  lease itself is excluded, so a watcher polling for a dead agent cannot make
  the session look alive.
- `run_watch(..., idle_exit=600)` compares that fingerprint each poll. A change
  restarts the window. After `idle_exit` seconds with no change it prints
  `AGENT_LOOP_STOP_hub-inbox` with `"rearm": true` and returns 0, instead of
  renewing. A superseded holder still exits 2 with `"rearm": false`.
- CLI: `--idle-exit` seconds, default 600. `idle_exit` below one poll interval
  is refused. There is deliberately no way to disable it: a watcher that
  renews forever is the bug this ticket exists to prevent.
- Docs: `docs/development.md` watch section and `hub.py help watch`.

## Operational consequence

Agents that idle between turns (any chat-driven agent) will see their watcher
exit after the idle window and should simply re-arm on their next turn; the
stop line is the signal. An idle session's lease then lapses normally and
another agent may take it, which is the point of the ticket.

## Remaining limitation

Takeover is slower than the rejected sweeper: the idle window plus up to the
remaining session lease (default 10 + 30 minutes). RL-013's problem statement
only requires that a dead holder's session becomes takeable.
